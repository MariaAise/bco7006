## Rationale for Redesign

This plan replaces the previous Session 3 layout. Key changes and the reasoning behind each:

- **Scope reduced** from six topics to four, with two more given only brief acknowledgement. Students entering this session have only seen variable assignment; expecting them to absorb operators plus four full data structures in three hours is unrealistic and produces low retention.
- **The 40-minute peer-teaching block on dictionaries is removed.** The provided peer-teaching notebook relies on `for` loops, `def`, `isinstance`, and recursion — all of which are taught in Session 4. Asking students to teach with tools they have not yet learned creates confusion rather than mastery. Peer teaching as a format is better suited to a later session once students have a foundation to teach from.
- **The "present-the-book-chapter" block is replaced with active live-coding in Colab.** Reading reference material is set as pre-class work; class time is for hands-on practice.
- **Examples throughout use business analytics framing** (products, prices, customers, carts) from the first minute, anchoring abstract syntax to the unit's purpose.
- **The mini-project at the end is a single integrated scenario** (a tiny online store), not four siloed tasks. This forces students to combine the data structures rather than treat them in isolation.

## Items Deferred or Moved

**Deferred to Session 4:** `for` loops and `if`/`else` are introduced today only as "recipes" for dict iteration and the shipping rule. Both are taught properly next session. The mini-project will be revisited in Session 4 with these tools properly in hand.

**Removed from this session:** nested dictionaries beyond two levels, hashability theory, custom recursive comparison functions, and the 40-min peer-teaching block. These are either too advanced for week 2 or rely on Session 4 material. Nested dicts can return when motivated by JSON file reading in Session 4 or pandas in later sessions.

**Reframed:** set operations (union, intersection, difference) are demonstrated through realistic BA scenarios (customers across months) rather than as abstract set algebra.
